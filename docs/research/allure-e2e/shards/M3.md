### M3.1: Quais media types de anexo são suportados (application/json, text/plain), como se usa AddAttachment e há limites de tamanho?

- **Verdict:** `text/plain` e `application/json` são suportados e exibidos no relatório. Em .NET (página NUnit), `AddAttachment` tem overloads por caminho ou por bytes, e a doc recomenda sempre informar o media type. Nenhum limite de tamanho foi encontrado; a única frase sobre restrições trata de tipos de arquivo. Tipo sem suporte vira link de download.
- **Evidence Items:**
  1. **Claim:** `text/plain` e `text/*` são media types de texto simples suportados.
     - **Excerpt:** "Media types: `text/plain`, `text/*`."
     - **Source:** `https://allurereport.org/docs/attachments/ (2026-11-13)` (`verified`)
  2. **Claim:** `application/json` é suportado na categoria de documentos, junto com XML e YAML.
     - **Excerpt:** "Media types: `text/xml`, `application/xml`, `application/json`, `application/yaml`."
     - **Source:** `https://allurereport.org/docs/attachments/ (2026-11-13)` (`verified`)
  3. **Claim:** Tipo sem suporte não tem preview; o relatório mostra link de download.
     - **Excerpt:** "For any unsupported type, a Click to download attachment link will be displayed instead of a preview."
     - **Source:** `https://allurereport.org/docs/attachments/ (2026-11-13)` (`verified`)
  4. **Claim:** Existe media type dedicado para exchanges HTTP (`application/vnd.allure.http+json`). A construção via API documentada é Java 3.0+ (`Allure.addHttpExchange()`); equivalente .NET não encontrado.
     - **Excerpt:** "Media type: `application/vnd.allure.http+json`."
     - **Source:** `https://allurereport.org/docs/attachments/ (2026-11-13)` (`verified`)
  5. **Claim:** Comparação visual no .NET usa `AddScreenDiff`, que recebe esperado, atual e diff.
     - **Excerpt:** "AllureApi.AddScreenDiff("expected.png", "actual.png", "diff.png");"
     - **Source:** `https://allurereport.org/docs/attachments/ (2026-11-13)` (`verified`)
  6. **Claim:** Media type define como o anexo aparece no relatório; a extensão define o nome ao salvar; a doc recomenda sempre informar o tipo.
     - **Excerpt:** "The media type affects how the data will be displayed in the test report," / "the filename extension is appended to the filename when user wants to save the file." / "it is recommended to specify each attachment's type."
     - **Source:** `https://allurereport.org/docs/nunit-reference/ (2026-11-13)` (`verified`)
  7. **Claim:** Nenhum limite de tamanho consta nas páginas consultadas; a frase sobre restrições trata de tipos, não de tamanho.
     - **Excerpt:** "Allure Report does not enforce any limitations on what files can be attached to a test report,"
     - **Source:** `https://allurereport.org/docs/attachments/ (2026-11-13)` (`inferred`: ausência verificada só nas páginas consultadas)
- **Gaps / Edge Cases:** Limite de tamanho não documentado; não assumir valor. Overloads de `AddAttachment` em .NET vêm de paráfrase do resumo WebFetch, sem citação literal. Página de anexos é cross-version (navegação Allure 2, notas Allure 3) e não confirma o pacote .NET no Allure 3. Excerpts são retornos do WebFetch, não conferidos byte a byte com a página.

     - **Source:** `https://allurereport.org/docs/steps/ (2026-11-13)` (`verified`)
  2. **Claim:** O relatório mostra steps em ordem cronológica, preservando o aninhamento.
     - **Excerpt:** "In the test report, Allure displays steps in chronological order, preserving the nesting structure."
     - **Source:** `https://allurereport.org/docs/steps/ (2026-11-13)` (`verified`)

     - **Source:** `https://allurereport.org/docs/steps/ (2026-11-13)` (`verified`)

### M3.3: Quais são os ParameterMode Default, Masked e Hidden, e como tratar valores que mudam a cada execução?

- **Verdict:** `Default` mostra parâmetro e valor na tabela. `Masked` mostra o parâmetro e oculta o valor; a página recomenda o modo para dados sensíveis, como senhas. `Hidden` remove parâmetro e valor do relatório, mas o valor continua em `allure_results` se o diretório for publicado. Para valores que mudam a cada execução, a doc só oferece `excluded`, que afeta a comparação de histórico; a página NUnit diz que esse argumento é usado só pelo TestOps, então o efeito no relatório Allure 3 não está confirmado.
- **Evidence Items:**
  1. **Claim:** `Default`: parâmetro e valor aparecem na tabela, junto com os demais parâmetros.
     - **Excerpt:** "the parameter and its value will be shown in a table along with other parameters."
     - **Source:** `https://allurereport.org/docs/nunit-reference/ (2026-11-13)` (`verified`)
  2. **Claim:** `Masked`: parâmetro visível, valor oculto. A página recomenda o modo para valores sensíveis.
     - **Excerpt:** "the parameter will be shown in the table, but its value will be hidden."
     - **Source:** `https://allurereport.org/docs/nunit-reference/ (2026-11-13)` (`verified`)
  3. **Claim:** `Hidden`: parâmetro e valor não aparecem no relatório.
     - **Excerpt:** "the parameter and its value will not be shown in the test report."
     - **Source:** `https://allurereport.org/docs/nunit-reference/ (2026-11-13)` (`verified`)
  4. **Claim:** `Hidden` não protege o dado: o valor pode ser extraído de `allure_results` se o diretório for publicado.
     - **Excerpt:** "it is still possible to extract the value from the allure_results directory if you publish it."
     - **Source:** `https://allurereport.org/docs/nunit-reference/ (2026-11-13)` (`verified`)
  5. **Claim:** `excluded=true` impede o parâmetro de entrar na comparação com o resultado anterior no histórico.
     - **Excerpt:** "if true, Allure will not use the parameter when comparing the current result with the previous one in the history."
     - **Source:** `https://allurereport.org/docs/how-it-works-test-result-file/ (2026-11-13)` (`verified`)
  6. **Claim:** Na página NUnit, `excluded` é usado só pelo TestOps. O efeito no relatório Allure 3 não está confirmado.
     - **Excerpt:** "This argument is only used by Allure TestOps."
     - **Source:** `https://allurereport.org/docs/nunit-reference/ (2026-11-13)` (`verified`)
  7. **Claim:** A Runtime API (`AllureApi.AddTestParameter`) adiciona parâmetros também a funções sem atributos do NUnit; a sobrecarga aceita nome, valor e modo.
     - **Excerpt:** "the Runtime API can be used for adding the parameters even to functions without the NUnit's attributes."
     - **Source:** `https://allurereport.org/docs/nunit-reference/ (2026-11-13)` (`verified`)
  8. **Claim:** Para valores voláteis (IDs, timestamps), a opção documentada é `excluded=true`; mascarar com `Masked` não resolve a variação, pois só oculta o valor. Tratamento por normalização é síntese própria.
     - **Excerpt:** "if true, Allure will not use the parameter when comparing the current result with the previous one in the history."
     - **Source:** `https://allurereport.org/docs/how-it-works-test-result-file/ (2026-11-13)` (`inferred`: síntese)
- **Gaps / Edge Cases:** Nenhum tratamento oficial de valores voláteis além de `excluded`; efeito no Allure 3 não confirmado (página NUnit cita TestOps). Mapeamento de `ParameterMode.Default/Masked/Hidden` para `default/masked/hidden` no JSON é `inferred` a partir do formato. Exemplo `AllureApi.AddTestParameter("password", "qwerty", ParameterMode.Masked)` veio só do resumo de busca. Normalização de valores é prática própria, não doc.

### M3.6: Como mensagem, stack trace e failExceptions aparecem em falhas e quebras?

- **Verdict:** O resultado guarda `statusDetails.message` (texto curto, como o nome da exceção) e `statusDetails.trace` (stack trace completo), com status `failed`, `broken`, `passed`, `skipped` ou `unknown`. No Allure 3, o erro do teste vira step sintético: título = mensagem; stack trace e diff dentro. Fica aninhado no step que falhou com a mesma mensagem ou trace; senão vai para o fim da lista. `failExceptions` decide se exceção em step vira Failed ou Broken, mas a regra por tipo de exceção e a página de configuração não foram confirmadas.
- **Evidence Items:**

     - **Source:** `https://allurereport.org/docs/how-it-works-test-result-file/ (2026-11-13)` (`verified`)

  4. **Claim:** Em step por atributo ou lambda, o status vira Failed ou Broken conforme `failExceptions`.
     - **Excerpt:** "the step becomes Failed or Broken according to the failExceptions configuration parameter."
     - **Source:** `https://allurereport.org/docs/nunit-reference/ (2026-11-13)` (`verified`)
  5. **Claim:** Em steps, o status depende do tipo da exceção; a doc não diz qual tipo gera qual status.

  10. **Claim:** No NUnit, assertion falha vira Failed e exceção não tratada vira Broken.
     - **Excerpt:** não há citação literal; paráfrase do resumo de busca: "failed assertions get a Failed status and unhandled exceptions get Broken"

Conteúdo exato que o pacote .NET grava em `message` e `trace` não verificado. Exibição de erro no Allure 2 não coberta (seção de erro marcada Allure 3).
